# Белый экран Telegram Desktop до загрузки Mini App

## Problem

Пользователь Telegram Desktop 7.0.4 на macOS прислал скриншот белого окна при
открытии ЮБуст Раннера. В `analytics_events` не появилось событие
`client_error`, а в nginx не было соответствующей цепочки запросов ресурсов.
При этом другой реальный macOS Mini App (`platform=macos`, viewport `401×644`)
в тот же день загрузил игру, отправлял heartbeat и завершил забег.

## Root Cause

Сбой происходит до выполнения `src/main.js`: Telegram Desktop может показать
пустой WebView или его старый кэш до загрузки внешнего CSS и модулей. Страница
задавала тёмный фон только во внешнем `styles/style.css`, поэтому на этом этапе
видимым состоянием оставался стандартный белый фон движка. Android-специфичный
текст fallback дополнительно вводил desktop-пользователя в заблуждение.

## Solution

- В `index.html` добавлен независимый inline `boot-splash` с тёмным фоном.
- Фон `html/body` теперь задаётся inline до любых сетевых ресурсов.
- Версии URL `style.css` и `main.js` изменены, чтобы Telegram не поднял старый
  закэшированный первый экран.
- После успешного `UI.showStart()` splash удаляется; при ошибке его заменяет
  универсальный fallback с выходом в обычный браузер.
- Для диагностики добавлен `fetch`-резерв, если `sendBeacon` недоступен.

## Prevention

Первый видимый кадр Mini App не должен зависеть от внешнего CSS, модулей,
Telegram SDK или canvas. При каждом изменении загрузочного контура проверять
Chromium и WebKit в узком viewport и сохранять тест, подтверждающий наличие
inline тёмного splash и cache-buster ресурсов.
