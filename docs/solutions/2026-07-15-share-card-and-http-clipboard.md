# Шеринг: счёт на солнце + копирование, которого не было без HTTPS

## Problem
Два дефекта на самом виральном экране игры.

1. **Карточка не читалась.** Главное число забега (то, ради чего карточку вообще
   скриншотят и репостят) рисовалось поверх диска солнца, и тёмные полосы диска
   разрезали цифры пополам. Линии сетки-пола шли сквозь блок «Ты пережил».
2. **Кнопка «ПОХВАСТАТЬСЯ» теряла ссылку.** На проде (голый HTTP) она молча
   скачивала PNG и не копировала ничего — на экране при этом не менялось ничего,
   то есть выглядела как сломанная кнопка. Виральная петля рвалась в самой
   дорогой точке: картинка уходила в чат без ссылки на игру.

## Root Cause

**1. Карточка.** Солнце рисовалось центром в `y=360` радиусом `200` (диск 160..560),
а счёт — в `y=400`, «ОЧКОВ · N М» — в `y=532`. То есть весь блок счёта лежал внутри
диска по построению. Полосы диска (`fillRect` от `SUN_Y` вниз) шли прямо по цифрам.
Сетка-пола начиналась с `y=560` и рисовалась до низа поверх всего остального.

**2. Копирование.** `navigator.clipboard` существует **только в secure context**.
Прод раздаётся по `http://31.130.148.55` → `window.isSecureContext === false` →
`navigator.clipboard === undefined`. Проверено на живом сайте:

```
isSecureContext: false · navigator.clipboard: undefined
navigator.share: undefined · crypto.randomUUID: undefined · execCommand: доступен
```

Фолбэк `legacyCopy()` (textarea + `document.execCommand('copy')`) в коде **был**, но
подключён только к промокоду и «СКОПИРОВАТЬ ВЫЗОВ». `shareRun()` звал
`navigator.clipboard.writeText` напрямую: обращение к свойству `undefined` бросало
`TypeError`, его глотал `catch`, и путь молча заканчивался ничем. Классическая
цена копипасты одного и того же `try/catch` в трёх местах — третье забыли.

## Solution

**Карточка** ([sharecard.js](../../src/game/sharecard.js)):
- Солнце ужато и опущено (`SUN_Y=355, SUN_R=130`) — живёт строго в окне между
  строкой звания и плашкой счёта, частично уходит за плашку («садится за
  горизонт»), фирменные полосы остаются видны над ней.
- Контент встал на плашки (`plate()`): счёт — на `rgba(5,1,10,0.82)` с красной
  рамкой, «ты пережил» — на `rgba(5,1,10,0.72)`. Число держит контраст в любой
  зоне и переживает сжатие до превью в мессенджере.
- `plate()` рисует скругление вручную: карточка рендерится и в браузере, и офлайн
  через `@napi-rs/canvas` (`render-shot.mjs`), полагаться на `ctx.roundRect` в
  обоих сразу не стоит.
- Горизонт сетки поднят к `470`, чтобы плашки стояли «на земле».

**Копирование** ([main.js](../../src/main.js)):
- Единая точка `copyText(text)`: `navigator.clipboard` → фолбэк `legacyCopy()`.
  Все три кнопки (шеринг, промокод, вызов) ходят через неё.
- Кнопка шеринга подтверждает результат (`STR.copied`), как остальные: молчаливый
  фолбэк читался как «кнопка не работает».

## Prevention
- **`navigator.clipboard`, `navigator.share`, `crypto.randomUUID` требуют secure
  context.** Пока прод на HTTP, любой новый вызов этих API обязан иметь фолбэк.
  В `harness.mjs` есть тест: `navigator.clipboard.writeText` может встречаться в
  `src/main.js` **ровно один раз** — внутри `copyText()`. Добавишь прямой вызов
  мимо помощника — упадёт.
- Настоящее лечение — HTTPS: он разом чинит clipboard, `navigator.share`,
  `crypto.randomUUID` (сейчас ID игроков падают на слабый `Math.random`-фолбэк) и
  открывает Telegram Mini App. На GitHub Pages (HTTPS) всё это уже работает —
  расхождение поведения прод/Pages при отладке шеринга помнить.
- Правки карточки проверять глазами через `npm run shots` → `preview/share-card.png`.
  Текст поверх процедурной сцены проверять на **худшей** зоне (Даркнет — тёмная
  зелень), а не на дефолтной: на закате всё выглядит нарядно и проблема прячется.
