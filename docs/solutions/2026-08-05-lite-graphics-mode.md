# Лёгкий режим графики для слабых устройств

## Problem

Игроки на слабых Android-телефонах жаловались, что игра «тормозит». Адаптивный
менеджер качества (`src/engine/quality.js`) в игре есть, но он не закрывает
проблему полностью:

- он **реактивный** — первые секунды забега идут на стартовом тире, то есть
  ровно там, где игрок формирует первое впечатление;
- на «почти тянущем» железе он застревает между тирами: после фикса
  автоколебаний (2026-08) тир, с которого устройство уже сваливалось,
  закрывается — и телефон остаётся на тире, который тянет «еле-еле»;
- у игрока не было способа сказать «мне не нужна красота, дай fps».

Требования к решению: опционально (тумблер рядом со звуком), прод живой —
данные игроков не должны пострадать, графика не должна влиять на геймплей.

## Root Cause

Качество рендера управлялось только автоматикой по времени кадра. Ручного
переключателя не существовало, а единственная «ручка» — `CONFIG.QUALITY.START_TIER`
— общая для всех устройств и правится только релизом.

## Solution

Настройка **«Графика: АВТО / ЛЁГКАЯ»** в экране настроек сразу под «Звук».

- `Settings.graphics` (`src/game/settings.js`) — новый ключ в том же
  localStorage-блобе `CONFIG.STORAGE_KEY`, что звук и доступность. Дефолт
  `auto`, невалидное значение → `auto`. Старые блобы прод-игроков получают
  дефолт и ничего не теряют (стор мержит `{...DEFAULTS, ...saved}`), откат
  версии игры просто игнорирует незнакомый ключ. В Telegram CloudStorage
  настройка НЕ уезжает — она про конкретное устройство.
- Лёгкий режим реализован **оверлеем поверх тира 0**, а не пятым тиром:
  `CONFIG.QUALITY.LITE` (`DPR: 1`, `PARTICLE_CAP: 140`). Пятый тир сдвинул бы
  нумерацию тиров и сломал сравнимость с прошлой телеметрией `quality_tier`,
  а также смысл `START_TIER` и индексов `upFails`.
- `Quality.setMode('lite' | 'auto')` прибивает тир к 0 и закрывает потолок;
  `sample()` в лёгком режиме сразу возвращается — адаптация молчит, буфер
  канваса не переаллоцируется на ходу. Возврат в АВТО обнуляет память о
  провалившихся подъёмах, заморозку DPR, EMA и cooldown: иначе игрок,
  однажды заглянувший в лёгкий режим, навсегда остался бы на DPR 1.
- В лёгком режиме не запускается фоновое видео меню (декодирование видео —
  самый дорогой кадр на слабом GPU); тумблер гасит/возвращает его на ходу.
- Бот (`backend/server.js`): команда `/lite` объясняет режим и даёт кнопку,
  открывающую игру сразу в нём — `?lite=1` для приватного чата (`web_app`) и
  `startapp=lite` для групп. Игра читает это в `readLiteDeepLink()` и
  запоминает выбор: deep-link — такое же явное действие игрока, как тумблер.

Что режим НЕ трогает: скорость (`baseSpeed`, `MAX_SPEED`, creep), плотность и
спавн препятствий, `REACT_TIME`, хитбоксы, очки и множители, время и
решаемость капчи, миссии, анти-чит и верификацию забегов, `RULESET_VERSION`,
схему БД и API. Сезон и рейтинг продолжаются без пересчёта.

## Verification

- `npm run verify` зелёный; `preview/*.png` не изменились байт-в-байт — значит
  визуал в режиме АВТО остался прежним.
- Новые тесты в `test/harness.mjs`:
  - оверлей `CONFIG.QUALITY.LITE` применяется с первого кадра, дорогие эффекты
    выключены;
  - 2000 кадров смешанного джанка не двигают тир и не дают ни одного `onChange`;
  - возврат в АВТО поднимает тир до максимума на быстрых кадрах;
  - поля тира качества обязаны оставаться косметическими (whitelist) — попытка
    добавить туда «спавн реже» или «скорость ниже» роняет тест;
  - геймплейные модули (`obstacles`, `collectibles`, `boosts`, `captcha`,
    `stats`, `player`, `world`) не имеют права читать `graphics`;
  - контракт бот↔игра по deep-link (`?lite=1` / `startapp=lite`);
  - тумблер стоит сразу после звука, переключается, переживает перезапуск;
  - живой забег в лёгком режиме идёт (дистанция растёт) и не падает при
    возврате в АВТО на ходу.
- В браузере (локальный сервер, viewport 375×812, devicePixelRatio 2):
  backing store канваса `375×812` (DPR 1.0) в лёгком режиме и `563×1218`
  (DPR 1.5, тир 1) после возврата в АВТО; `?lite=1` на чистом сторадже
  включает режим и не запускает видео; блоб настроек сохранил прежние ключи;
  ошибок в консоли нет. На 360×640 экран настроек с шестой строкой помещается
  целиком.

## Побочная находка на проде: закэшированный index.html убивал bootstrap

Сразу после выкладки лёгкого режима проверка глазами игрока на
`https://31.130.148.55/` показала белый экран вместо игры и в консоли
`TypeError: Cannot set properties of null (setting 'textContent')` в
`main.js:1243`, а `window.__uboostBooted` оставался `false`.

Причина не в лёгком режиме, а в кэше: `index.html` кэшируется дольше `js`
(у html вообще нет `Cache-Control`, у модулей — короткий срок), поэтому у
игрока оказалась **старая разметка со свежим main.js**. URL модуля живёт внутри
закэшированного html (`src/main.js?v=…`), а nginx отдаёт по этому пути уже
новый файл. Новый `fillStaticCopy()` обращался к `$('set-graphics-label')`
напрямую — элемента в старой разметке нет, `null.textContent` бросает, и весь
bootstrap обрывается на первой же строке: игра не запускается вообще.

Лечение (коммит `fix: закэшированный старый index.html больше не убивает
bootstrap`): подписи статики ставятся через `setText()` (нет элемента — нет
подписи), кнопки читаются через guard, версия статики поднята до
`lite-graphics-1`. Тесты: эмуляция старой разметки (`getElementById` возвращает
`null` для новых id) и требование, чтобы версии css и js в `index.html`
совпадали.

Проверено на живом проде: свежая вкладка получила старый html из кэша и всё
равно загрузилась (`__uboostBooted: true`, консоль чистая) — просто без новой
строки настроек, которая появится после обновления html-кэша.

Остаётся открытым инфраструктурный вопрос: у `index.html` нет `Cache-Control`,
поэтому браузеры держат его эвристически долго. Правильное лечение —
`no-cache` для html в nginx, но это общий сервер с чужим проектом varonia,
поэтому менять конфиг нужно отдельной аккуратной задачей с бэкапом.

## Prevention

- Ручки качества добавлять в `CONFIG.QUALITY` (и читать с `??`-дефолтом —
  тест следит: при деплое свежий `quality.js` может встретить закэшированный
  старый `config.js`).
- Новый тир качества — только если готов пересчитать телеметрию: для «ещё
  дешевле/дороже» используй оверлей поверх крайнего тира.
- Любая новая настройка графики обязана оставаться косметической. Тесты
  «косметический whitelist» и «геймплейные модули не читают graphics» — это
  машинная гарантия обещания «графика не влияет на геймплей», не удаляй их.
- Deep-link из бота и его чтение в игре — контракт двух концов; переименование
  одного конца ломает второй молча, поэтому он закреплён тестом.
- **Любой новый обязательный элемент разметки — потенциальный белый экран** для
  игрока с закэшированным `index.html`. Добавил элемент — читай его безопасно
  (`setText()` / `dom.x?.`) и поднимай `?v=` парой css+js.
- Прод обновляется не пушем, а процедурой из `ops/DEPLOY.md` (VPS — не
  git-репозиторий). Перед деплоем сверяй, что реально стоит на проде: 2026-08-05
  он отставал от `main` на два коммита при «чистом» репозитории.
