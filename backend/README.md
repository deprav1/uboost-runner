# Сервер, рейтинг и Telegram-бот

Рабочий production-бэкенд — [`server.js`](server.js): один Node-процесс раздаёт
статику игры, хранит SQLite-рейтинг и аналитику, проверяет heartbeat забегов и
держит Telegram long polling. `worker.js` и D1-файлы оставлены как legacy-
прототип Cloudflare и не должны считаться эквивалентом production API.

## Переменные окружения

```text
PORT=8080
HOST=127.0.0.1
STATIC_ROOT=/opt/uboost
DB_PATH=/opt/uboost/backend/data/uboost.db
BOT_TOKEN=...
BOT_ADMIN_IDS=123456789,987654321
RULESET_VERSION=2026-07-17-v2
ANALYTICS_RETENTION_DAYS=90
ALLOWED_ORIGIN=https://31.130.148.55
GAME_URL=https://31.130.148.55/
TELEGRAM_IP_FAMILY=6
```

`BOT_ADMIN_IDS` — числовые Telegram `chat_id`, которым бот разрешает
админ-команды. Без allowlist они не работают. Отправь боту `/id`, чтобы узнать
свой chat_id для добавления в allowlist.

`TELEGRAM_IP_FAMILY=6` задан только на production VPS: его IPv4-маршрут до
`api.telegram.org` таймаутится, а IPv6 работает. В других окружениях переменную
можно не задавать — Node выберет маршрут автоматически.

### Админ-команды бота

Все доступны только `chat_id` из `BOT_ADMIN_IDS`, ответы форматированы HTML.

| Команда | Что делает |
| --- | --- |
| `/admin` (`/contacts`, `/winners`) | Топ-5 подтверждённых лидеров недели + их `@username`/Telegram ID. |
| `/stats` | Воронка за 7 дней: заходы → старты → забеги → шеры → CTA, уник. игроки, ср. дистанция, копирования промокода. |
| `/season` | Текущий `RULESET_VERSION`, окно доски, число забегов/verified/игроков. |
| `/export` | Контакты победителей недели в виде CSV (в чат). |
| `/void <run_id>` / `/void player <playerId>` | Снять `verified` с забега или со всех забегов игрока (модерация; доска пересчитывается). |
| `/notify …` | Собрать рассылку поздравлений (см. ниже). Ничего не отправляет — только превью с токеном. |
| `/confirm <токен>` | Подтвердить и отправить подготовленную `/notify` рассылку (токен живёт 5 минут). |

Формы `/notify` (двухшаговые — сначала превью, потом `/confirm`):

- `/notify winners <N> [текст]` — топ-N по суммарному пробегу. Плейсхолдеры в
  тексте: `{alias} {rank} {score} {distance}`. Без текста — дефолтное поздравление.
- `/notify user <@username|id> <текст>` — точечно одному человеку.
- `/notify campaign <имя> [N]` — кампания из `backend/campaigns/<имя>.json`
  (`message`/`parseMode`/`buttonText`/`buttonUrl`) топ-N победителям.

Безопасность рассылок: отправка идёт очередью с паузой (щадит лимиты Telegram);
получатели без `chat_id` (не нажимали `/start`) пропускаются; кампании
идемпотентны — один игрок не получит одно и то же поздравление дважды
(журнал `notifications_sent`). Точечные `/notify user` не журналируются и
дублирование не блокируют.

### Автоматические рассылки

Промо-цикл длится три дня и отсчитывается от первого забега текущего
`RULESET_VERSION`. После закрытия каждого цикла сервер:

1. один раз отправляет кампанию `life-winner` всем игрокам, которые завершили
   хотя бы один забег в этом цикле;
2. после первых трёх суток сезона один раз выбирает подтверждённый
   (`verified=1`) топ-10 по суммарному пробегу и отправляет кампанию `top10-3d`
   с сообщением о приставке. В следующих циклах призовая рассылка не повторяется.

Проверка границы запускается при старте сервера и затем раз в 15 минут.
Идентификаторы и уникальный индекс журнала исключают дубликаты при рестарте.
Если бот не может написать пользователю (тот не нажимал `/start`), сообщение не
считается доставленным.

## Правила рейтинга

- Публичная соревновательная доска содержит только `verified=1`.
- Публичная доска и challenge-ссылки содержат только анонимный `publicId`, не
  внутренний `player_id`/Telegram ID. Исторические `ref` мигрируются без потери
  счётчиков.
- Изменение имени, старт/heartbeat и сохранение результата требуют подписанного
  Telegram `initData` либо браузерного секрета; в БД хранится только его HMAC.
- `run_id` уникален: повторный `/v1/scores` возвращает прежний результат и не
  увеличивает суммарный пробег.
- `RULESET_VERSION` начинает отдельный сезон после изменения баланса.
- Игра сначала показывает топ-5, остальные загруженные строки раскрываются
  кнопкой.
- `notify-winners.mjs`, API и команды бота используют те же `verified` и
  `RULESET_VERSION`.

Heartbeat доказывает правдоподобный темп, но не является полной серверной
симуляцией. Перед денежными/ценными призами верхние результаты нужно проверять
отдельно.

## Проверка

```powershell
npm test
```

Помимо игрового harness запускается HTTP/SQLite integration-тест: verified-
доска, защита личности, отсутствие Telegram ID в публичном API, дедупликация
`run_id`, версия правил, ETag и защита админ-команды.

После запуска production проверять:

```text
GET /v1/health
GET /v1/leaderboard?period=week&limit=25
GET /v1/dashboard
```

## Данные и приватность

Сырой Telegram `initData` проверяется в памяти и не сохраняется. В БД остаются
Telegram ID/username для определения и связи с победителями, игровые результаты
и события. Production-таймер ежедневно запускает `backup-db.mjs`, проверяет
копию через `PRAGMA quick_check` и хранит 30 последних снимков. Для защиты от
потери самого VPS дополнительно нужен внешний backup.

Промокод показывается только когда реальная скидка создана в биллинге и
`CONFIG.PROMO.code` заполнен. Пустой код скрывает блок в игре, карточке и боте.
